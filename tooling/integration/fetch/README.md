# Current-source Fetch qualification

Run:

    python3 tooling/integration/fetch/run.py

Source is resolved from the same checkout and must retain the project's private directory mode (0700). The runner creates a new private Caches assembly, instantiates hash-pinned fixture templates with source/check/output path changes and the documented Build177 UI successor, and compiles both native Fetch fixtures from the current FetchPlugin.swift.

The original strict wrapper and its dependent order remain:

1. Installer17 uses the bundled fixed payload only, in a generated private parent.
2. Native14 consumes that exact generated installation.
3. Guards9 qualify current managed Fetch visibility and runtime checks.
4. Durable6 qualify native result persistence and interruption.
5. UI6, admission7 and recovery-cross15 complete the 74-case suite.

The original exact environment, original-store guards, ephemeral socket guard, source bindings, native-result checks and qualified Python/Node executable hashes are retained. Fixture pins bind routed text, the explicitly recorded UI successor, and newly compiled binaries. No assertion is removed or weakened. Native helper paths required by the reviewed environment remain explicit; no external runtime is downloaded or installed.

All generated runtime state stays in the unique Caches directory. The runner copies the fresh logs/results into .artifacts/integration and emits RESULT.json with numeric passed, failed and exitCode, complete current-source pins, sourceUnchanged and hash-bound evidence. It never reuses a prior RESULT.json. Originals under /Users/saleh/Documents/Noiee/checks/fetch/current-runtime remain untouched.

These checks use generated installer state and fake MCP/inference transports. They do not claim installed-app acceptance, live network Fetch behavior, original owner-store admission or model quality.

Build177 uses an explicitly recorded successor for the Fetch UI mock: setAttribute is supported and action lookup requires the labeled group with both controls. The six existing state, dispatch and Stop checks remain intact. The historical template and origin hash stay unchanged; TEMPLATES.json and generated adaptation receipts record both versions. This is a fixture compatibility change, not a runtime or gate-count change.
